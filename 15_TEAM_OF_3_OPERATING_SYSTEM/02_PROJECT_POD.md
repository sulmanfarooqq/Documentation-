# PROJECT POD

Every client project uses the same three-seat structure.

## Before build
A:
- confirms scope
- confirms payment
- confirms acceptance criteria
- confirms client access

B:
- designs implementation
- identifies dependencies
- estimates technical work

C:
- creates QA plan
- identifies release risks
- defines evidence

## During build
B is primary builder.
C reviews critical changes and tests continuously.
A manages client decisions, scope, and commercial changes.

## Before demo
C answers:
- Does the happy path work?
- What important edge cases were tested?
- What is known to fail?
- What evidence proves acceptance?

A checks:
- Is this exactly what was sold?
- Are there unpaid extras?

B checks:
- Is deployment stable?
- Can the system be supported?

## Handoff
A = client acceptance
B = technical handoff
C = QA/release documentation
