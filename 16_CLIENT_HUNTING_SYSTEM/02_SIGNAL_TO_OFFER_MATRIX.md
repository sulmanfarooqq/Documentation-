# SIGNAL → OFFER MATRIX

This document prevents the team from seeing a signal and then randomly pitching the entire Flow Vello service catalog.

## Rule

**One signal → one operational problem → one offer.**

| Signal | Problem hypothesis | Offer |
|---|---|---|
| Hiring RevOps | process/CRM complexity | CRM + workflow automation |
| Hiring SDRs | lead volume/follow-up load | Lead routing + follow-up automation |
| Hiring support | repetitive customer requests | AI support + escalation workflow |
| Hiring operations | manual internal work | Workflow automation |
| Explicit chatbot request | support/lead capture need | AI chatbot |
| Explicit WhatsApp request | messaging workflow need | WhatsApp automation |
| Explicit dashboard request | reporting visibility need | Executive dashboard |
| Explicit API/integration request | systems disconnected | Integration sprint |
| New ecommerce growth | order/support load | Order + support automation |
| New market expansion | process scaling | Lead/CRM automation |
| New product launch | operational workload | Launch workflow + dashboard |
| Website/project request | web delivery need | Website/custom software sprint |
| Repeated manual spreadsheet workflow | data-entry bottleneck | Internal workflow automation |
| Booking/admin bottleneck | appointment handling load | Booking + reminder automation |

## Signal confidence

### Level A — Explicit demand

They asked for it.

**Sell directly.**

### Level B — Strong evidence

Multiple signals indicate the problem.

**Sell with a specific observation.**

### Level C — Weak evidence

One ambiguous signal.

**Do not pitch aggressively. Research only enough to confirm.**

---

# OFFER RULE

Do not say:

> "We do AI, automation, dashboards, websites, chatbots, CRMs, custom software..."

Say:

> "I noticed X. We can fix Y with Z."

The prospect should understand the offer in one sentence.

---

# THREE-PERSON TECHNICAL CHECK

For a Level A/B opportunity:

A:
- commercial fit

B:
- technical feasibility

C:
- QA/proof/reusability

If B or C says the problem is not actually solvable within scope, A does not send the proposal.

This is how engineering quality protects sales instead of becoming an excuse to avoid sales.
